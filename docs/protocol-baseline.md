| A2A | https://a2a-protocol.org/latest/specification/ | Latest specification includes Send Message, Agent Card, `Part`, idempotency, error handling, capability validation, and versioning sections. | Pin watasu contract tests to the selected A2A v1.0 HTTP+JSON subset before implementing the submission gate. |
| JWS sender signatures | https://www.rfc-editor.org/rfc/rfc7515, https://www.rfc-editor.org/rfc/rfc7518, https://www.rfc-editor.org/rfc/rfc8037, and https://nodejs.org/api/crypto.html | JWS signing input is `BASE64URL(protected) + \".\" + BASE64URL(payload)`. ES256 uses ECDSA P-256 SHA-256 with fixed-width `R || S`. RFC 8037 defines `EdDSA` for JOSE with OKP keys and Ed25519 / Ed448 subtypes. Node.js crypto supports public JWK import and Ed25519 verification through `crypto.verify`. | Use detached compact JWS for sender signatures. Allow `ES256` and `EdDSA` with Ed25519 keys. | HTTPS ownership challenge fetch | https://nodejs.org/api/dns.html and https://nodejs.org/api/globals.html#fetch | Node.js provides stable `node:dns` name-resolution APIs and a global `fetch`. | Use built-in DNS lookup and fetch only; add no dependency. Before fetching a webhook ownership challenge, require `https:`, resolve all host addresses, reject unsafe IP ranges, and fetch with `redirect: \"manual\"`. |
| DNS TXT ownership challenge fetch | https://nodejs.org/api/dns.html | Node.js provides `resolveTxt` through the DNS promises API. | Use built-in DNS TXT resolution only; add no dependency. Flatten TXT chunks before comparing the expected ownership token. |
| Hosted service identity signed headers | https://nodejs.org/api/crypto.html on 2026-06-15 | Node.js documents `crypto.createHmac` and `crypto.timingSafeEqual`; `timingSafeEqual` is suitable for comparing HMAC digests or secret values when surrounding code avoids timing leaks. | Use built-in Node crypto only for deployment signed service identity headers. | MCP Streamable HTTP transport | https://modelcontextprotocol.io/specification/2025-11-25/basic/transports on 2026-06-15 | MCP 2025-11-25 defines Streamable HTTP as the standard HTTP transport. | PostgreSQL pool wiring | https://node-postgres.com/features/pooling on 2026-06-15 | node-postgres documents using a single bounded `Pool`, returning checked-out clients, and using `pool.query` for single queries to avoid client leaks. | Keep watasu core on the generic `query(text, values)` interface. | Test runner | https://vitest.dev/guide/ | Vitest is the Vite-native test framework and supports TypeScript-oriented unit/contract/snapshot tests. | Use Vitest for unit, contract, security regression, and workspace tests. |

## Hosted operations baseline

| Area | Checked source | Current result | Deployment decision |

| Secrets and environment variables | https://render.com/docs/configure-environment-variables | Render environment variables protect credentials from being committed and environment groups can share variables across services. | Put real values only in Render environment variables or environment groups. | Database and backups | https://render.com/docs/postgresql-creating-connecting | Render Postgres is fully managed; paid databases provide point-in-time recovery and logical exports. | Database env wiring | https://render.com/docs/blueprint-spec | Blueprint env vars can reference a Render Postgres database property with `fromDatabase` and `property: connectionString`; Render marks that property as the private-network connection URL. | Wire `WATASU_POSTGRES_URL` through `fromDatabase` instead of committing any database URL or credentials. |
| Retention cron | https://render.com/docs/cronjobs and https://render.com/docs/blueprint-spec | Render cron jobs require a cron expression, run in UTC, support environment variables, and should execute a command that exits when done. | Custom domain and TLS | https://render.com/docs/custom-domains | Render custom domains require adding the domain, configuring DNS, and verifying it; Render automatically creates and renews TLS certificates and redirects HTTP to HTTPS. | Use `api.watasu.ai` as the first dedicated API subdomain, verify DNS in Render, and rely on managed TLS. | GitHub Actions CI | https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax and https://docs.github.com/en/actions/reference/security/secure-use | GitHub workflow permissions can be restricted at the workflow level, and GitHub's secure-use guidance treats workflow inputs and third-party actions as a supply-chain boundary. | Hosted HTTP security headers | https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy, https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Content-Type-Options, https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy, and https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control on 2026-06-15 | MDN documents CSP as a response policy for controlling allowed resources, `X-Content-Type-Options: nosniff` as MIME-sniffing protection, `Referrer-Policy: no-referrer` as omitting referrer information, and `Cache-Control: no-store` as avoiding response storage by caches. | Send `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and `Cache-Control: no-store` on hosted API responses by default. Keep canary checks strict so deployment drift is visible before private-alpha exposure. |

## Current local runtime

- `node --version`: `v22.22.0`
- `pnpm --version`: `10.31.0`

The repo targets Node.js 24 LTS, but workspace scripts are kept compatible with the local Node.js 22 LTS runtime so tests can run before the developer environment is upgraded.

`package.json` intentionally records the local/runtime compatibility floor. Deployment configuration, CI matrices, and release notes should treat Node.js 24 LTS as the hosted production target.

## Local workflow helpers

- `pnpm review:self` resolves the vendored or global gstack review checklist path and prints the standard validation and diff commands.
- `pnpm pr:draft` creates a draft PR with `gh` when authenticated. If `gh` is not authenticated, it prints `gh auth login -h github.com` and the exact GitHub PR URL for the current branch.
